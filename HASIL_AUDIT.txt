#### AUD-002: Status Persistensi Transaksi (Pratinjau vs Tersimpan)

- Hasil Verifikasi Faktual:

- Tindakan Remediasi: Menjaga isolasi kalkulasi pratinjau dan memastikan penulisan ke Google Drive hanya terjadi ketika pengguna secara sadar menekan aksi cadangkan / sinkronisasi.

### 3. ARSITEKTUR INTEGRASI PENYIMPANAN OFFLINE-FIRST & CLOUD SYNC

src/
├── auth/
│   └── supabaseClient.ts     # Inisialisasi Supabase client & dynamic credentials
├── components/
│   └── ModalForm.tsx         # Dialog modal aksesibel (pengganti prompt(), keyboard friendly)
├── storage/
│   ├── types.ts              # Zod schema, types, validasi integer Rupiah & kuantitas fisik
│   ├── checksum.ts           # SHA-256 canonical hashing deterministik
│   ├── storageAdapter.ts     # Interface StorageAdapter & default state payload
│   ├── indexeddbAdapter.ts   # Penyimpanan lokal IndexedDB (3 stores: doc, backup, outbox)
│   ├── supabaseAdapter.ts    # Sinkronisasi cloud PostgreSQL Supabase (@supabase/supabase-js)
│   ├── syncEngine.ts         # Mesin sinkronisasi dua arah otomatis (outbox queue, anti-duplikasi)
│   ├── googleAuth.ts         # Google Identity Services (GIS) Token Client & lifecycle
│   ├── googleDriveAdapter.ts # [DEPRECATED UNTUK TRANSAKSI AKTIF] Backup manual Google Drive v3
│   ├── mockStorageAdapter.ts # In-memory adapter (khusus unit testing simulasi)
│   └── index.ts              # Export modul terpadu
scripts/
└── migrate-sample-data.mjs   # Skrip migrasi data sampel ke format schema tervalidasi
tests/
└── playwright/
    └── transactions.spec.ts  # Skrip pengujian E2E skenario offline, modal, dan sync

1. Alur Penyimpanan Primer (Offline-First via IndexedDB):
   - Data transaksi ditulis seketika ke document_store IndexedDB lokal di peramban pengguna.
   - Dipanggil navigator.storage.persist() saat aplikasi dimuat agar data tidak terhapus otomatis oleh peramban.
   - Transaksi dijamin tersimpan tanpa jeda, tanpa risiko kegagalan jaringan internet.
2. Mesin Sinkronisasi Cloud Dua Arah (Supabase Free Tier Rp0):
   - Setiap mutasi lokal didaftarkan ke outbox_queue dengan idempotencyKey dan deviceId.
   - SyncEngine mendengarkan event online/offline dan menjalankan siklus sinkronisasi berkala (30 detik).
   - Menolak Last-Write-Wins (LWW) diam-diam; konflik versi dideteksi secara eksplisit.
3. Pencadangan Multi-Cloud & Pemulihan Aman:
   - Fitur ekspor/impor langsung file JSON tersedia di menu Pengaturan.
   - Pencadangan manual ke Google Drive REST API v3 tetap dipertahankan penuh.
   - Safe Snapshot Enforcement: Pemulihan data mewajibkan pembuatan snapshot pengaman terlebih dahulu; jika snapshot pengaman gagal dibuat, restore otomatis dibatalkan.

### 11. SESI RESOLUSI SKEMA KOLOM data_version & version (AUD-20261101-05)

  Tabel public.toko_documents di Supabase dibuat dengan kolom bernama version, sedangkan SupabaseAdapter mengirimkan payload dengan nama kolom data_version. PostgREST menerapkan validasi skema ketat sehingga menolak operasi upsert jika kolom tidak cocok persis.

  1. Self-Healing di SupabaseAdapter:
     - loadData(), saveData(), pushDocument(), pullDocument(), createBackup(), dan listBackups() diperbarui agar secara cerdas mencoba kolom data_version dan otomatis fallback ke kolom version jika PostgREST melaporkan kolom tidak ditemukan.
  2. Penyempurnaan Skrip Migrasi 001:
     - Ditambahkan perintah ALTER TABLE public.toko_documents ADD COLUMN IF NOT EXISTS data_version bigint DEFAULT 1; dan penyelarasan otomatis kedua kolom.
