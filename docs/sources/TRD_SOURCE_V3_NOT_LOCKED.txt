## 1. Prinsip yang mengikat desain
1. Angka uang = turunan murni dari kejadian append-only oleh **satu engine**.
2. Preview = Save: modul engine yang sama di browser dan server; server menghitung ulang **sebelum commit** dan menolak bila digest berbeda.
3. Browser tidak pernah menyambung ke database. Semua akses lewat server lokal.
4. Tidak ada rahasia di kode, browser, repo, atau prompt.
5. Data nyata hanya setelah **Gerbang Data Nyata** (§20) lulus.
6. Hal yang belum terbukti ditulis **BELUM TERVERIFIKASI**.

---

## 2. Arsitektur

```
Browser  ───────►  Server Next.js lokal (127.0.0.1:3000)
(UI + engine untuk preview)    ├ Komponen server: memuat data, hidrasi ke klien
                               └ Server Actions: commit, tutup periode, preview koreksi
                                        │  DATABASE_URL (peran app_server, rahasia di .env.local)
                                        ▼
                    Supabase Free PostgreSQL (cloud)  ◄── hanya data nyata
                       RLS, trigger append-only, RPC SECURITY DEFINER

Pengembangan/uji: sama persis, tetapi database LOKAL (Supabase CLI atau Postgres Docker) + seed.dev.sql
```

### 2.1 Alur baca
1. Komponen server memuat `event` + tabel `ev_*` + `period_close` + `snapshot_*` lewat peran `app_server` (SELECT).
2. Data dihidrasi ke komponen klien sebagai `EngineInput` (hanya di memori; tanpa localStorage untuk data bisnis).
3. Browser dan server menjalankan `calculate()` yang sama.

### 2.2 Alur tulis
1. Form menghasilkan `command_id` (UUID) dan **draft kejadian**; browser menjalankan `calculate(existing + draft)` dan mencatat `preview_digest`.
2. Server Action `commit({command_id, kind, events, expected_max_seq, as_of, preview_digest, confirm?})`:
   Zod → muat data → `max(seq) == expected_max_seq`? → `|as_of − jam server| ≤ 10 menit`? → `calculate(existing + draft)` → bandingkan digest → panggil `rpc_commit_command`.
3. Digest berbeda → `PARITY_MISMATCH` + angka kanonis; **tidak ada yang disimpan**.
4. Sukses → `{event_ids, max_seq, digest}`.

### 2.3 Alur tutup periode
Server Action `closePeriod`: hitung snapshot (engine, versi saat ini), tentukan `lengkap`/`sebagian` (lengkap bila semua produk relevan CUKUP), tolak "Catat sebagai selisih" bila masih ada BELUM CUKUP atau komponen tak pasti, lalu `rpc_close_period` (kunci + cek data basi + koreksi kas atomik + snapshot dalam satu transaksi).

### 2.4 Alasan
| Pilihan | Alasan | Ditolak |
|---|---|---|
| Server lokal | Tanpa login, satu-satunya cara aman: tidak ada URL yang terbuka. Tidak butuh hosting, jadi Rp0 dan tanpa batas CPU | Hosting publik tanpa login (data terbuka) |
| Mode server Next.js | Server Actions dan komponen server tersedia; secret tetap di server | Static export (hanya perlu bila hosting statis) |
| Satu proyek Supabase untuk data nyata | Sesuai keputusan; Free cukup untuk satu toko | Dua proyek, demo |
| Driver Postgres langsung (`postgres`) | Transaksi dan RPC dari server; PostgREST tidak dipakai | supabase-js (tak perlu klien API) |
| RPC SECURITY DEFINER | Tulis atomik; peran aplikasi tak bisa INSERT/UPDATE/DELETE langsung | Hak tulis langsung ke tabel |
| Zod | Satu skema untuk form dan server | Validasi manual |

## 6. Database

### 6.1 Skema (SQL ada di `supabase/migrations/`)
Relasional bertipe; JSON hanya untuk `snapshot_explain.tree` (turunan) dan `command.result`.

| Kelompok | Tabel |
|---|---|
| Identitas | `toko`, `product` (boleh diubah, diaudit), `audit_log`, `backup_log` |
| Kejadian | `event` (`seq`, `kind`, `occurred_at`, `occurred_precision`, `recorded_at`, `command_id`, `supersedes_id`, `correction_of_close_id`, `source`) |
| Detail | `ev_stock_check`, `ev_purchase` + `ev_purchase_item`, `ev_damage`, `ev_used`, `ev_expense`, `ev_other_income`, `ev_deposit`, `ev_price_change`, `ev_no_sales_statement`, `ev_cash_adjustment`, `ev_setting` |
| Periode | `period_close` (tanpa tumpang tindih) + `snapshot_line`, `snapshot_product_state`, `snapshot_explain` |
| Idempotency | `command` |

Tidak ada: tabel demo, kolom pemilik, tabel/kolom non-tunai (diuji).

### 6.2 Kendala dan trigger
FK komposit `(…, toko_id)` (tidak ada lintas toko); CHECK nilai; `pcs` turunan; indeks `(toko_id, seq)` dan `(toko_id, occurred_at, seq)`. Trigger: append-only di semua tabel kejadian/snapshot/command/log/toko (UPDATE, DELETE, TRUNCATE ditolak); rantai versi valid; periode tertutup (kejadian di dalamnya wajib bertanda koreksi); produk diaudit dan id/toko tidak bisa berubah.

### 6.3 Konsekuensi append-only: data uji hanya lokal
Data yang sudah masuk tidak bisa dihapus lewat aplikasi. Maka:
- Pengembangan, seed (`seed.dev.sql`), seed beban, dan semua test berjalan di database **lokal**.
- Cloud (satu-satunya proyek) tidak pernah diberi seed. `supabase db push` hanya menerapkan migrasi.
- Bila data uji sempat masuk ke cloud, **reset sebelum data nyata pertama** (RUNBOOK §6.2). Sesudah data nyata pertama, reset dilarang.

### 6.4 Koneksi
Cloud: `DATABASE_URL` peran `app_server` lewat **Shared Pooler mode session** (`app_server.<project-ref>`, port 5432; IPv4 pada Free **[R]**), `postgres` `max: 3`. Kata sandi dibuat pemilik (`alter role app_server with password …` di SQL Editor), tidak di repo/chat. Lokal: koneksi langsung ke database lokal.

## 7. Akses dan RLS
- `anon` dan `authenticated`: **tidak punya hak apa pun** (tabel, fungsi, bahkan USAGE skema), tanpa policy. Diuji.
- RLS aktif di semua tabel (diuji).
- `app_server`: SELECT (kecuali `command`), INSERT `product`/`toko`, UPDATE `product(name, archived_at)`, EXECUTE `rpc_commit_command` dan `rpc_close_period`. **Tidak ada** INSERT/UPDATE/DELETE langsung pada event dan tabel kejadian (diuji).
- Tabel `command`: tanpa policy dan tanpa grant; hanya RPC.
- Skema `public` dipakai; karena `anon`/`authenticated` tidak punya akses, PostgREST (Data API) tidak mengekspos data. Opsional: matikan Data API di Dashboard (tidak dipakai).

## 8. RPC (kontrak)
`rpc_commit_command(p_toko, p_command_id, p_kind, p_payload, p_expected_max_seq, p_actor)` → `{event_ids, max_seq, replayed}`: kunci advisory per toko, idempotency (id sama + isi sama = hasil lama; isi beda = `TS_COMMAND_REUSED`), `TS_STALE` bila `max(seq)` berbeda, insert header + detail bertipe.
`rpc_close_period(p_toko, p_command_id, p_period_start, p_period_end, p_completeness, p_engine_version, p_input_max_seq, p_snapshot, p_actor)` → `{close_id}`: kunci, `TS_STALE`, `TS_PERIOD_GAP`, koreksi kas atomik (`cash_adjustment` di snapshot), snapshot beku.
Kode error: `TS_BAD_PAYLOAD`, `TS_NO_TOKO`, `TS_COMMAND_REUSED`, `TS_STALE`, `TS_BAD_CHAIN`, `TS_CLOSED_PERIOD`, `TS_BAD_CORRECTION`, `TS_PERIOD_GAP`, `TS_APPEND_ONLY`, `TS_UNKNOWN_KIND`.

## 9. Server Actions (kontrak)
Hanya dijalankan oleh server lokal; semuanya memvalidasi dengan Zod dan menganggap input tidak tepercaya.
- `commit` (§2.2). Server mengisi `correction_of_close_id` otomatis bila kejadian berada di periode tertutup; perubahan periode tertutup, void, atau edit wajib `confirm: true`. Kejadian hanya-tanggal dinormalisasi ke 12.00 WIB.
- `closePeriod` (§2.3).
- `previewCorrection`: baca saja; delta engine-sekarang − snapshot.
- `exportData`: JSON/CSV semua kejadian.
- Kode hasil: `VALIDATION`, `STALE`, `PARITY_MISMATCH`, `CONFLICT`, `NEED_CONFIRMATION`, `CLOSED_PERIOD`, `DB_UNAVAILABLE`, `INTERNAL`.

## 10. Kontrak engine
Tipe dan invarian: `src/engine/contract.ts`. Fixture: `tests/golden/gt.json`.
- Fungsi murni `calculate(EngineInput) → EngineOutput`; `asOf` selalu masukan.
- Rupiah dan pcs bilangan bulat aman; pelanggaran = gagal keras.
- Dua kolam per produk; keluar proporsional; pembulatan setengah ke atas pada nilai, sisa tetap di nilai.
- **Waktu:** UTC; periode `[Senin 00:00 WIB, Senin berikutnya 00:00 WIB)`; hanya-tanggal = 12.00 WIB, seri oleh `seq`; periode pertama dimulai pada pengamatan awal paling awal.
- **Uang:** semua penjualan tunai. Kas toko = penjualan + pendapatan lain − keluar bersumber kas toko − setoran ± koreksi kas. Uang siap setoran = kas toko sebelum setoran yang dievaluasi.
- Digest: SHA-256 JSON kanonis angka kunci (tanpa id/seq).

### 10.1 Aturan waktu (satu tempat)
| Aturan | Isi | Bukti |
|---|---|---|
| Zona | Tampil WIB (UTC+7, tanpa DST); simpan UTC | – |
| Periode | `[Senin 00:00 WIB, Senin berikutnya 00:00 WIB)`: awal inklusif, akhir eksklusif | Uji DB (8b) + fixture ST1 |
| Periode pertama | Dimulai pada pengamatan awal paling awal | ST4 |
| Tutup lebih cepat | Akhir periode = waktu tutup; berikutnya mulai saat itu; periode harus bersambung | Uji DB `TS_PERIOD_GAP`, ST3 |
| Hanya-tanggal | Disimpan 12.00 WIB (05:00 UTC) | ST2 |
| Urutan | `(occurred_at, seq)`; `seq` = urutan pencatatan server | ST2 |
| Tanggal mundur | Periode terbuka boleh; periode tertutup → koreksi yang ditautkan otomatis | Uji DB 8, 8b, 9b |
| Tanggal masa depan | Ditolak bila > 5 menit dari jam server (validasi server) | ST5 (belum dijalankan) |
| `as_of` preview | Dari klien; server menerima selisih ≤ 10 menit | Tahap 3 |
| Interval penjualan | (pengamatan sebelumnya, pengamatan ini]; milik periode yang memuat akhir interval | Fixture engine |
| Ekor waktu | (pengamatan terakhir, E]; E = sekarang / waktu setoran / waktu tutup | SC4, SC5 |
| Tampilan | "Rabu 8 Okt 2026, 10.00" WIB, tanpa detik | – |
- **Versi:** SemVer; `engine/v1` dibekukan saat periode data nyata pertama ditutup; perubahan angka sesudahnya = `v2`; snapshot menyimpan versi; delta memakai engine milik snapshot; CI menghitung ulang fixture snapshot dan harus identik. Delta: `engine_sekarang(P_k) − (snapshot_k + delta yang sudah masuk snapshot berikutnya)`, diturunkan, tidak disimpan.

## 13. Keamanan

Fakta: **tanpa login, aplikasi tidak otomatis privat.** Satu-satunya kontrol akses adalah bahwa server hanya berjalan di mesin sendiri.

| Kontrol | Rincian |
|---|---|
| Ikatan jaringan | Jalankan `pnpm dev -H 127.0.0.1` / `pnpm start -H 127.0.0.1`. Tanpa `-H`, Next dapat mendengarkan di semua antarmuka. **[?]** diuji di Tahap 3: akses dari perangkat lain dalam jaringan harus gagal |
| Tidak ada publikasi | Tanpa tunnel, port forwarding, atau hosting |
| Rahasia | `DATABASE_URL` hanya di `.env.local` (di `.gitignore`); `scan-secrets.mjs` di CI dan pra-commit |
| Database | RLS + REVOKE total untuk anon/authenticated; app_server hanya SELECT + RPC |
| Server Actions | Zod; batas ukuran; pemeriksaan Origin bawaan Next **[S]**; tidak mengandalkan UI |
| Header | `X-Frame-Options`, `nosniff`, `Referrer-Policy`, `noindex` di `next.config.ts` |
| Rantai pasok | Pin, audit, Dependabot; tanpa `next/og`, tanpa gambar jarak jauh |

### 13.1 Model ancaman localhost

| Ancaman | Mitigasi | Status |
|---|---|---|
| Perangkat lain di jaringan | Ikat `127.0.0.1` | diuji Tahap 3 **[?]** |
| Situs lain di browser yang sama memanggil localhost (CSRF) | Server Actions memeriksa Origin; tanpa header CORS; tanpa cookie sesi | **[S]** |
| **DNS rebinding** (domain penyerang diarahkan ke 127.0.0.1; Origin sama dengan Host sehingga lolos pemeriksaan Origin) | **Penjaga Host**: middleware menolak (403) setiap permintaan yang `Host`-nya bukan `localhost:<port>` atau `127.0.0.1:<port>`. Uji: `curl -H "Host: evil.example"` → 403 | **Wajib; belum diimplementasi [?]** |
| Port diteruskan otomatis (VS Code/Codespaces/dev container/VM jarak jauh) | Terminal harus berjalan di **komputer sendiri**, bukan sandbox atau mesin jarak jauh; periksa tab Ports dan `ss -ltnp` | Gerbang §20 |
| Pengguna lain pada komputer yang sama; malware; ekstensi browser | Tidak dicegah (tanpa login). Pakai akun OS sendiri + kunci layar | **Batas diterima** |
| Kebocoran `.env.local` | `.gitignore`, `scan-secrets` (repo + riwayat) | diuji |

Jika nanti ingin diakses dari ponsel atau dipublikasikan, itu keputusan baru dan **wajib** menambah kontrol akses terlebih dulu.

## 14. Validasi dan error
Zod di form dan Server Action; CHECK DB garis terakhir; engine tidak melempar untuk kondisi bisnis (anomali adalah data). Pesan Indonesia sederhana. Koneksi gagal: "Coba lagi" (retry aman karena idempoten), tanpa antrean lokal. Jejak penting disimpan di DB (`audit_log`, `command`).

### 14.1 Gangguan koneksi atau cloud (perilaku terdefinisi dan diuji)
Aplikasi berjalan lokal, tetapi **data nyata ada di cloud**. Karena itu:

| Kondisi | Perilaku | Tidak boleh |
|---|---|---|
| Tidak tersambung saat memuat | Layar "Tidak tersambung" + `[Coba lagi]`. Tidak ada data lama (tanpa cache persisten) | Menampilkan angka usang tanpa label |
| Terputus saat tab sudah terbuka | Data tetap terlihat berlabel "Data per [waktu]; tidak tersambung"; **semua penyimpanan dinonaktifkan**; draft tetap di layar | Menyimpan lokal diam-diam atau antrean tersembunyi |
| Putus tepat saat menyimpan | "Belum pasti tersimpan. Coba lagi." Percobaan ulang memakai `command_id` yang sama → idempoten: hasil lama atau ditulis sekali | Menulis ganda |
| Proyek terjeda | Layar khusus + petunjuk runbook | – |
| Lambat/menggantung | `connect_timeout` 10 detik dan `statement_timeout` 15 detik (belum diset) → `DB_UNAVAILABLE` | Menunggu tanpa batas |

Tes: Server Action dengan DB tak terjangkau mengembalikan `DB_UNAVAILABLE` dan **tidak menyimpan apa pun**; E2E mode offline; ulang `command_id` tidak menduplikasi (idempotensi sudah diuji di DB). Konsekuensi: data nyata tidak aman hanya karena aplikasi berjalan; Gerbang §20 mensyaratkan uji ini.

## 15. Performa
Muat seluruh kejadian di server per sesi (ribuan baris; 10.011 baris terbaca ±3 ms di DB lokal), hitung di browser. Tanpa cache uang. Optimasi (mulai dari snapshot terakhir) hanya bila terukur lambat.

|---|---|---|
| 1 | Ekspor JSON/CSV dari aplikasi; pengingat setelah tutup periode; disimpan di perangkat/Drive milik sendiri | Hanya bila dilakukan |
| 2 | `scripts/backup.sh` (pg_dump + age; kunci publik di repo, **kunci privat hanya pemilik**), dijalankan manual atau dijadwalkan di mesin sendiri | **Bukan jaminan** |
| 3 | `backup.yml` GitHub (opsional) | **Bukan jaminan**: jadwal bisa terlewat **[R]** |
| 4 | Aplikasi menampilkan usia backup dari `backup_log` | Menampakkan kegagalan |
| 5 | Latihan pemulihan `scripts/restore-drill.sh` (CI setiap PR) | **Teruji** |
| 6 | Uji pemulihan ke DB kosong sebelum data nyata dan tiap bulan | Manual |

**Sudah teruji (Postgres 16 lokal):** backup → enkripsi → dekripsi → pulih ke DB kosong → checksum identik (kejadian, butir belanja, periode, snapshot, command); trigger append-only, RLS, dan hak akses ikut pulih. **Pemulihan data-saja dilarang** (penjaga periode tertutup menolak); gunakan dump penuh. Target pemulihan: Neon Free atau proyek Supabase baru; peran `app_server`, `anon`, `authenticated`, `service_role` serta ekstensi `pgcrypto` dan `btree_gist` harus ada lebih dulu.

Target jujur: kehilangan data maksimal sampai backup/ekspor terakhir yang berhasil. Tanpa pemulihan ke titik waktu. Penghapusan tidak sengaja dicegah trigger; perintah destruktif manual lewat Dashboard tidak terlindungi.
